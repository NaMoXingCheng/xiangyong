# 测试脚本

这个目录放着开发过程中攒下来的验证脚本。**它们不是单元测试框架**，而是针对具体问题的「现场取证工具」——
每个脚本都对应过至少一个真实缺陷，用来把「感觉不对」变成「哪一行不对」。

> 截图产物（`截图/`，上百 MB）不进仓库，见根目录 `.gitignore`。

---

## 三种运行方式

### ① 一键跑（推荐入口）

包装器会**自己起一个隔离实例**（独立端口 + 临时数据目录，不碰你的 `data/`），跑完自动拆干净。

```bash
node 测试脚本/跑界面验收.js     # 界面视觉验收（51 项）
node 测试脚本/跑音效测试.js     # 音效 / 背景音乐（43 项）
node 测试脚本/跑报告测试.js     # 年度报告三套巡检（版式 + 收尾 + 交互）
```

这三个都需要先 `npm install`。前两个会起 Electron，约 30 秒。

### ② 纯 Node（最快，不需要 Electron）

```bash
node 测试脚本/测评分.js         # 关系评分引擎边界用例（79 项）
node 测试脚本/测承诺规则.js     # 承诺识别规则的边界用例（42 项）
node 测试脚本/测热词头像.js     # 热词选词 + 自定义头像（29 项）
node 测试脚本/测AI显存.js       # 显存治理状态机 + 接口契约（35 项）
node 测试脚本/测防多开.js       # 单实例锁
node 测试脚本/测GPU降级.js      # GPU 崩溃自动降级不会误伤
```

### ③ Electron 离屏巡检（需要自己先起服务）

这类脚本用 Electron 把界面渲染出来再量，**必须先有一个跑着的服务**，并用 `SHOT_URL` 告诉它地址。

```bash
# 终端 A：起服务
npm run server           # 或 npm start

# 终端 B：跑巡检
SHOT_URL=http://127.0.0.1:4322 \
  env -u ELECTRON_RUN_AS_NODE \
  ./node_modules/electron/dist/electron.exe --no-sandbox 测试脚本/验收界面.js
```

| 脚本 | 量什么 |
|---|---|
| `验收界面.js` | 右键换头像、热词榜 AI 入口、年度报告成品页 |
| `测音效.js` | 音效与 BGM：泛音是否整数倍、电平下限、响度滑杆联动 |
| `测报告版式.js` | 封面日期、背景页码、动态页数、结尾寄语 |
| `测报告收尾.js` | 控制条静止后隐身、放映结束提示、节奏、待办折叠 |
| `测报告交互.js` | 页码是否「移上去才显示」、换页是否两页并存转场 |

> `env -u ELECTRON_RUN_AS_NODE` 不能省：如果环境里设了这个变量，Electron 会退化成纯 Node，
> `require('electron')` 里的 `app` 是 `undefined`，脚本会报一个看起来毫无关系的错。

## 需要真模型（慢，会占显存）

```bash
node 测试脚本/测寄语真AI.js       # 年度报告结尾寄语，端到端（约 2GB 显存）
node 测试脚本/测锐评.js           # 真相数据 → 提示词 → 输出
node 测试脚本/测模型校验.js [档位] # 无合格证的模型是否走「就地校验补证」而非重下
```

`测寄语真AI.js` 支持验分发包：

```bash
TA_APP_ROOT=/path/to/打包目录 node 测试脚本/测寄语真AI.js
```

它会**照常从源目录取真实数据与模型**（分发包里本来就不该有 `data/`），只把应用代码换成打包目录那份。

## 排查工具（给数据，不给结论）

出问题时用这些「量一下」，比盯着代码猜快得多。

| 脚本 | 用途 |
|---|---|
| `测掉帧.js` | 卡顿体感：不看平均帧率，看**帧间隔分布**（p50 / p95 / 最长帧 / 交互延迟） |
| `测消融.js` | 卡顿消融实验：逐项关掉可疑视觉效果，看 CPU 占用怎么变 |
| `找动画.js` | 找出「到底哪些元素一直在跑无限动画」 |
| `抓点击报错.js` | 抓「每次点击都报的那个错」 |
| `截报告.js` | 年度报告逐页截图 + 量出大数字的真实字号 / 居中偏差 / 是否溢出 |
| `放大看.js` | 放大某个元素的渲染细节，并打印它的计算样式 |
| `探数字字形.js` | 量各字体数字墨迹高度，判断是不是「老式数字」（高低不齐的元凶） |
| `探数字基线.js` | 打印 `.rs-num` 的字体度量，校准数字偏上的补偿量 |
| `预览截图.js` | 把运行中的界面离屏渲染成 PNG，核对视觉 |
| `拍热词卡.js` | 单独截热词卡片 |
| `看热词.js` | 起隔离实例打 `/api/person/<id>`，打印热词榜实际输出 |
| `测对话框.js` | 验证替代 `prompt` / `confirm` 的自绘对话框 |
| `看GGUF元数据.mjs` | 直接解析 GGUF 头部元数据，确认模型文件本身对不对 |

## 写新脚本的两条约定

1. **头部写清「用法」和「为什么需要这个脚本」** —— 半年后你只会记得「这里有个脚本」，
   不会记得它当初在防什么。
2. **不要写死本机路径** —— 用 `path.join(__dirname, '..')` 定位项目根。
   这条是硬要求：脚本要能在别人机器上跑，也是它能进仓库的前提。
